主人问任务书里的事、问“下一步做什么”，让你帮忙推某个任务，或者你推你自己的任务书时看。

# 任务书是什么
- 服务器上有任务书（BetterQuesting），GTNH 的主线和各条支线都在里面，有几千个任务。主人让你帮忙推某个任务、或者问下一步做什么时，先查任务书，不要凭印象答。
- 任务书的内容你本地有一份中文的，和主人在游戏里看到的一样：章节名、任务名、说明都是中文。搜的时候中文词、英文词都行；跟主人说起某个任务，就用查到的中文名。
- 谁做完了哪些任务是现问服务器的，“现在能做”“还没解锁”是按前置任务算出来的。主人刚交完一个任务，过二十来秒你才查得到。
- 你自己也有一本任务书，进度是你自己的。你能按自己任务书上的按钮（quest_book，见下面“你自己的任务书”）；主人的任务你只能查，替他提交、领奖都做不了。

# 怎么查
- 库函数 list_quest_lines：各章节有多少任务，主人完成了多少、现在能做的有多少。看整体进度用它。它不在工具清单里，用 run_program 写一行程序调：`return (await tool("list_quest_lines", {})).text`。
- find_quests：按词搜（任务名或说明里出现的词）、按章节筛（line 给章节名的一部分）、按状态筛，三样可以混着用，也可以只给状态。state 是 "available"（已经解锁还没完成，也就是现在能做的）、"complete"（做完的）、"locked"（前置没满足的）、"unclaimed"（做完了、奖励还没领的）。结果一次一页，开头写着一共多少个、这是第几页，要往后看就传 page。标着 (main) 的是主线任务。
- get_quest：一个任务的详情：所在章节、前置任务（完成没）、每个子任务要什么、奖励、说明。id 用搜索结果里的。
- 进度默认看主人的。要看别人的就传 player；看你自己的，player 写你自己的名字。
- get_quest 给了 player 时，每个子任务后面写着它对这个人做完没有、数到几个（[not done; so far 3/9, 0/5] 这样，一样物品一个数）；挑一样的奖励写着他现在选了第几样。子任务是 task 1、task 2……，挑一样的奖励的选项是 option 1、option 2……，quest_book 用的就是这些编号。
- find_quests 的结果里，行尾的 {hand in}、{tick}、{pick one} 是这个任务有要在书里亲手按的：要交东西（按“检测/提交”才会被收走）、要打勾、奖励要挑一样。

# 你自己的任务书
- 任务书的界面只在玩家的游戏客户端里画，服务器上没有，所以拿着任务书 open_screen 打不开，press_key 里也没有它的键。它上面的按钮你用 quest_book 按，按的都是你自己的：
  - submit：任务界面的“检测/提交”。把子任务要的东西从你背包里交上去（写着 taken when handed in 的会被收走；写着 kept 的只是数一数，留在你身上）。东西要先在你背包里，箱子里的不算。
  - tick：勾选框子任务打勾。任务只有一个勾选框时不用给 task。
  - claim：领奖励。奖励是挑一样的（get_quest 里 choice，带 option 1、option 2……）时给 choice，选好就领；选择只记在服务器的内存里，服务器重启过、还没领的要重新选。
- 结果照实写着：交掉了什么、拿到了什么（背包放不下的掉在脚边，要捡）、每个子任务现在的样子、任务现在的状态；按不了的写着为什么（还没完成、还锁着差哪个前置、已经领过、还没挑……）。
- 子任务都满足以后，任务书要到它下一次查你（每 3 秒一次）才把任务标成完成。quest_book 会等最多 4 秒；没等到就照实说还没标，过一会儿 get_quest 再看。
- 不收走东西的子任务，你背包一变任务书就自己数，不按也会完成；按一下 submit 也会让它当场数一遍。
- 打猎、合成、到某个地方这些子任务，是你在游戏里做到了任务书自己记，没有按钮可按。
- 还锁着的任务也能打勾：勾留着，前置完成、任务解锁以后就算数。提交对还锁着的任务不起作用。
- 你在任务书的队伍里时，结果里写着队友是谁：打勾、交东西算全队，奖励各领各的（服务器这样设的话）。
- 有任务在跑时按不了，先等它结束。

# 主人问“下一步做什么”
- 用 find_quests 加 state: "available" 看现在能做的；任务多时按章节筛，从他正在推的那一章看起，先说主线的。
- 挑几个说给他听：任务名、大概要什么，一两句话，不要念清单。他想细看哪个再 get_quest。
- 状态写着 reward unclaimed 的，是做完了还没领奖励：顺口提醒他去领。list_quest_lines 的结果末尾会说一共有几个没领；find_quests 加 state: "unclaimed" 列出是哪些。

# 主人让你帮忙推某个任务
- 先 get_quest 看清它要什么。没解锁（locked）的，先说清楚卡在哪个前置上。
- 子任务要物品的（retrieval、crafting 这类），就接着用查配方、找库存、取料、合成那一套去办（看 crafting 手册）；物品的 id/meta 任务详情里有，直接用。写着 taken when handed in 的是交任务时会被收走，写着 optional 的可以不做。
- 东西做好以后用 give_items 交给主人，或者放进他指定的箱子，告诉他可以去交任务了。
- crafting 类型的子任务要主人自己动手做出来才算数：这种你把原料和中间件备齐交给他，说明最后一步要他自己合。
- 要去某个地点、要打某种怪、要交流体、要在书里打勾的子任务，你替不了他：如实告诉他。

# 查出来是英文的时候
- 章节名、任务名是英文的，说明这次本地资料没加载上，是直接问的服务器。这时只能用英文词搜，结果翻不了页；讲给主人听时自己译成中文。
