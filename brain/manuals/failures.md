任务失败了看不明白该怎么办，或者你死了、服务器重启了之后看。

# 先分清普通困难与异常
- 未达到动作的前置条件不等于 Bug。按失败原因检查相关事实：背包可用空间、目标是否还在、材料和工具、站位距离、可见面、保护和机器状态；修正条件后再尝试，不必每次查完整套。
- 取不到或捡不到时尤其要看背包：新物品、返还物和拆分操作都可能需要额外空间。容量不足就先整理，把暂时不用的东西存好；只对仍未获得的数量重试。已经明确是路径不可达的，不能一概归因于满包。
- 处理正常条件后仍不符合游戏规则，或者回执与实际冲突（例如要求2却投8、取到0却说全部完成），才作为异常记 report_problem。记录请求、实际结果、前后状态、尝试过什么；证据不足写清楚，不把猜测的原因写成结论。工具没有提供必要动作或信息，也可以记录为能力缺口。

# 错误码
任务失败时会带一个错误码和一句原因：
- unreachable：走不到目标，或者目标太远（消息里会写 teleport closer first）。太远就先 go_home 传送到附近；否则换一个能到的目标，或者问人。
- stuck：试了多次没有进展。先 get_status、look_around 看看情况再重试一次；还不行就问人。
- no_tool：没有能挖这种方块的工具。消息里写着这个方块要哪一类工具、几级（比如 GregTech 的机器外壳要 "wrench" 扳手 2 级），和你身上每件工具为什么不行；detail 里有方块、坐标和 needs。去仓库找那一类工具（find_in_storage 可以按矿辞查，扳手是 craftingToolWrench），找不到就问人要。石头矿石这一类用匠魂（TConstruct）的镐，见 terrain 手册。
- no_material：要放、要用的东西不够（detail.missing 是缺多少或缺哪些）。去箱子或抽屉里取，或者问人。
- inventory_full：没有足够的可用携带空间，可能是新堆栈、合成返还物或暂存/拆分放不下；不是每次都指36格完全满。先按消息和 get_status 整理，存放不需要的物品，再处理剩余部分。施工工具支持 dropoff 时可指定卸货容器，其他工具不一定有这个参数。
- container_full：目标箱子或抽屉放不下（抽屉只收它已经装着的那几种，或者放进还没指定物品的空格）。换个容器，或者问人。
- denied：服务器或别的 mod 不让你动这一格（挖、放、右键、开箱子、用抽屉都可能），同样的动作再做一遍结果一样。消息里写着是什么拒绝的：
  - 服务器的出生点保护：消息写明出生点和范围（主世界里离出生点几格以内、x 和 z 从几到几、所有高度），detail.protection 是同样的数。服务器有 op 时，不是 op 的玩家在这个范围里点、挖、对着方块放都会被拒绝，你不是 op。probe_block 看得出一格在不在里面。
  - 领地（ServerUtilities）、封了箱的抽屉这类是别的 mod 拒绝的，只知道被拒绝了。ServerUtilities 的领地里，领地主人设成盟友或队员的玩家能挖、放、开箱子（他执行 /team status 你的名字 ally 或 invited；入队是 run_command 发 `team join 队伍名`）。
- invalid：参数不合法，或者服务器拒绝了指令（比如 go_home 去一个不存在的 home）。看消息，改正了再来。
- interrupted：你下线、死亡，或者被带到了别的维度。先看状态，再决定要不要重启任务。
- internal：身体那边自己出了错，不是你的问题。告诉人，不要反复重试。
- busy：服务器刚启动，配方索引还没建好。过几秒再试。

条件没变化时别原样反复失败。能自己整理、补料或换合法站位的先处理；仍卡住或需要主人的决定，再把已查事实和剩余问题写清楚（report，要人拿主意的带 question: true）。挖、填、平地、照图纸盖这类任务可以重入：问题解决后用同样的参数再启动，只会做还没做完的部分。

# 死了
- 你死了会在一两秒后自动重生（位置按服务器规则），当前任务以 interrupted 失败、队列清空，背包里的东西可能掉在死亡地点。先看状态，再决定要不要回去捡（collect_items）、要不要重启任务。

# 服务器重启了
- 服务器重启后你会自动上线，没做完的任务会自己从头重新开始，不用你再启动一遍。
- 挖、填、平地这类任务只是接着做；但 withdraw 会再取一份，haul 手上的那趟货会留在你身上。重启后看一眼背包，多出来的放回去。
