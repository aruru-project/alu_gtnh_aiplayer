主人只给了目标（“做一个 XX”“帮我弄点 XX”），要你自己查配方、挑做法、找材料、合成或者开机器加工时看。

主人只说要什么、没说怎么做时，怎么做由你来定。没有一条现成的“最佳路线”：工具只告诉你事实（有哪些做法、基地里现在有什么机器、东西放在哪），选哪条是你的判断。下面写的是玩家挑做法时会考虑的事，是参考，不是规则；拿不准就问主人。

# 一层层往下查
1. find_item 确认是哪个物品，拿到 id 和 meta（物品名是中文的，直接用主人说的词搜；几个都像时问主人）。
2. find_recipes 看它有哪些做法。结果按加工方式一种种列，不分好坏；每种写着基地里有没有做它的机器、那台机器什么状况。每条配方有一个 # 编号。
3. 挑一条你觉得合适的（怎么挑见下一节），看它要哪些原料。
4. find_in_storage 一次把这几样原料都查了（“any xxx”的用矿辞名查）。它看的是整个基地。
5. 库存里没有的原料，回到第 2 步查它怎么做。这样一层层往下，直到每样东西要么库存里有，要么你知道怎么做。
6. 一口气看整棵树：`total_materials { id, meta, count }`（库函数：直接调这个名字，或者程序里 `await tool('total_materials', …)`）。它把这样东西往下展开到底，库存里有的先扣掉，结果里是：没定过做法的东西（每样摆着它的几种做法）、还缺的原料、缺的能力（基地里没有机器的做法、要供的流体和现在罐里有多少）、活儿清单（按先后分几批，每批按做法分组）。
   - 每样东西用哪条配方不是它选的：先看你这一次在 recipes 里点名的，再看“基地的做法”里记的（这样东西的 → 当现成的就停 → 它这一类零件的 → 同料时用哪种 → 总的先后），都没有而它只有一条配方就照做；再不是就不展开，列进 NOT DECIDED 等你定。
   - 你定了以后：记进基地的做法（set_base_method）就以后都照用；只想这一次用，就写进 recipes。再算一次，它接着往下走。
   - 接着管道、漏斗的容器里的东西另列一栏、不计入；机器里的不算库存。stock: false 是不看库存、从零算。数量沿树乘下去，一轮出几个按轮数取整，模具和工具只算一个。用凿子变出来的那一步不是配方、没有编号，写在 chisel 里（见下面“凿子的花纹”）。
7. 动手：取料（withdraw_items）→ 从最底下那一层做起（craft_item、process_items），一步一个任务。

走一遍的样子（做 1 个直升机桨叶）：
- find_recipes 桨叶 → 手工合成：4 精炼铁柄 + 3 钢螺丝 + 1 钢齿轮，要螺丝刀。
- find_in_storage 这四样 → 螺丝、齿轮、螺丝刀有，精炼铁柄没有。
- find_recipes 精炼铁柄 → 压模机：9 钢锭一根，要模头（转轴）留在机器里。基地有一台进阶压模机，有电。
- find_in_storage 钢锭、模头（转轴）→ 钢锭有，模头（转轴）没有。
- find_recipes 模头（转轴）→ 手工：4 玄钢板 + 1 模头（杆）+ …… → 再查玄钢板、模头（杆）……
- 查到模头（杆）：库存没有，配方是流体固化器用熔融钢浇。那条配方后面写着固化器的罐里现在有多少熔融钢；罐里没有，就接着查熔融钢怎么来（find_recipes 给 fluid）、基地里有没有能化的钢。一路查下来真的没有路了，**再停下来问主人**，把查到的这条链说给他：“桨叶要 4 根精炼铁柄，柄要模头（转轴），它要一个模头（杆）——仓库没有，做它要熔融钢，罐里是空的，也没有流体提取机。你那有现成的吗？”

# 挑做法时玩家会想什么
- **每个成品耗多少料。** 同一样东西不同做法差很多：钢板卷板机 1 锭 1 板，手工锤 2 锭 1 板。find_recipes 每条配方后面括号里的 per xxx 就是每个成品耗多少。
- **要不要为它新做模具或工具。** 压模机省料，可要是得先为它做一个模头（又是好几步、还要流体），做两个零件就不值得；手边有锤有锯，手工敲两个更快。要得多的时候反过来。
- **会不会用掉现成的机器或成品。** 配方的原料里有一台机器、一件做好的工具或零件时，仓库里那台多半是主人留着用的，用掉就没了。主人没说过可以用的，问一句。
- **流体从哪来。** 配方要流体（mB …）时，find_recipes 在那条配方后面写着做它的那台机器里现在有多少：单方块看它自己的罐，多方块看输入仓。没有的话，这种流体本身也能查做法（见下面“流体”一节）。流体从一台机器到另一台有三条路：机器界面上的自动输出开关（往它的输出面推）、主人搭的管道和泵、用流体单元装了倒过去；通没通看两头罐里的量（下面“流体”一节的例子里有）。
- **手工工具配方费料、磨工具。** 有读得懂、确实做得了的机器时，玩家一般走机器；没有时手工是正常的办法。
- **哪些是主人自动化的一部分。** 标着 AUTOMATED 的箱子、总线、机器：从里面取一些通常没事，往里放会和管道送来的混在一起；主人交代过怎么用的照他说的，没交代过的问一句。机器里放着的模具、燃料是主人摆好的，用完放回原处。
- **没见过的机器。** find_recipes 写 CAN TRY 的（别的 mod 的机器、熔炉）身体读不到状态，只能放进去试；配方没列的东西（熔炉的燃料）要自己带上。见 screens 手册。
- **要一把工具而仓库里没有。** 做一把最简单的就够用（不用做电动的）；用哪种材质看仓库里什么多。
- 一种方式下配方很多（工具每种材质一条，几百条）时，用 way 加 contains 缩小：find_recipes 给 way "有序合成"、contains "钢"。结果一页 10 条，要看完就翻页。想知道一样东西能拿来做什么：库函数 find_uses（不在工具清单里，run_program 写一行 `return (await tool('find_uses', { id, meta })).text`；再给 way、contains、circuit 看具体的配方）。

# 基地的做法
这个基地怎么做东西的记录：主人教的，和你自己定过的。重启、历史压缩都不丢；一类零件、当现成的、同料时用哪种、总的先后这几种每一轮都列在提示词里。base_methods 看全部，set_base_method 记一条、改一条（同一个键再记一次）、删一条（remove 给它的键）。四种：
- 一类零件走哪种做法：`{ part: "plate", way: "卷板机", from: "ingot", by: "owner", why: "一锭一板" }`。part 是矿辞前缀（find_item 写着一样东西登记在哪些矿辞名下，plateSteel 的前缀是 plate）；from 是从哪种料来，不写就是那种做法里列在最前的一条；material 只管一种材料（"Steel"）。双层板、小撮粉这些是另一种零件，板和粉的记录管不到它们。
- 当现成的、不往下做：`{ ready: "ingot", by, why }`（矿辞前缀；也可以是一个矿辞名 "ingotSteel"，或者一样物品 "mod:name/meta"）。total_materials 走到它就停，记成要现成的原料。主人问“整条线要多少资源”、从零算时，停在锭、粉、宝石就是这个。目标自己不算。
- 两种做法用的料一样时用哪一种：`{ use: "有序合成", over: "组装机", noTools: true, by, why }`。一样东西两种做法都做得出、两边消耗的东西和数量一样、出的一样多（工具、编程电路不算料）时用 use 那种；noTools 是只在 use 那条不用工具时才这样。料不一样、或者 use 那条要工具时它不起作用，往下看总的先后。
- 一样具体的东西用哪条配方：`{ id, meta, recipe: 配方的 # 编号, by, why }`（流体给 fluid）。配方册重新导出后编号会变：记下的是这条配方的样子，用的时候对回现在的编号；配方没了会照实说。
- 总的先后：`{ order: ["有序合成", "组装机"], by, why }`。没有更具体的记录时，排在前面、做得出那样东西的做法先用。
- 一台机器是干什么的：`{ machine: { x, y, z }, does: "专门做导线，电路锁在 24", feed: 进料的容器, collect: 收货的容器, keep: "里面的橡胶别动", by }`。find_machines、inspect_block 看到这台机器时带着这一条，total_materials 的活儿清单里也带。
- by 是谁定的：主人说的写 "owner"，你自己定的写 "self"。find_recipes 查一样东西时，基地的做法里定过它（或者它这一类零件）会在结果第二行说。

# 流体
- 流体和物品一样能查。find_item 按中文名、英文名或内部名都找得到流体，结果里它带着内部名（如 熔融钢 [fluid molten.steel]）。NEI 里那个“流体展示”物品（NotEnoughItems:neiFluidDisplay）只是配方画面上代表流体的图，不是能拿的东西；拿它去查，答的是那种流体。
- 怎么来：find_recipes 给 fluid（名字或内部名）代替 id，列出产出它的配方，按加工方式分。同名的流体不止一种时（“熔融钢”有两种），结果会把它们列出来让你挑内部名。
- 能做什么：库函数 find_uses 给 fluid。
- 罐里现在有什么：inspect_block、list_containers、find_machines 的结果里写着每个罐多少 mB 什么流体、容量多少（机器的罐、储罐、超级缸都一样）。一台机器没写罐，是它没对外报；它自己存的全部数据在 inspect_block 的 detail 里（见 screens 手册）。
- 一台机器现在在做哪条配方：它的加工方式、输入里的流体或物品、编程电路号，三样一筛就是那一条。`find_uses { fluid: "oil", way: "蒸馏塔", circuit: 9 }` 列出对得上的配方和它全部的输入输出（物品和流体各多少）；从产物那头查是 `find_recipes { fluid: "含硫轻燃油", way: "蒸馏塔", circuit: 9 }`，再加 contains（原料里的一个词）缩小。find_machines 在读得出输入流体的机器下面直接写着这句查询。
- 算总料时流体也算：`total_materials` 的 recipes 里放上“出这种流体的那条配方”（或者基地的做法里给这种流体记了配方），它就按 mB 往下乘（一轮出 144 mB、要 180 mB 就是 2 轮）；没有的流体列在 fluids to supply 里，写着现在哪个罐里有多少。目标本身也可以是流体（给 fluid，count 是 mB）。

走一遍的样子（2 个钢板做钢环；是例子，不是规矩）：
- find_recipes 钢环 → 流体固化器：36 mB 熔融钢一个，要模具（环）留在机器里。后面写着固化器的罐里现在有多少熔融钢。
- 模具在哪：find_in_storage 模具（环）→ “在流体固化器 west 面的覆盖板‘基础槽位扩展’里”。覆盖板里的东西不在机器自己的格子里，取它用结果里写的那个容器（带 side 和 sneak），见 containers 手册。
- 熔融钢怎么来：find_recipes { fluid: "molten.steel" } → 流体提取机：1 钢板化成 144 mB。
- total_materials 钢环 ×4，recipes 给这两条 → 1 个钢板（144 mB）正好 4 个环。
- 动手：process_items 流体提取机化钢板。产物是流体，没有物品可取：任务照样是完成，结果里写着“做出来的是流体，在机器的罐里，现在多少 mB”。流体这时在**提取机**的罐里。
- 流体怎么到固化器：
  - 提取机的界面上有流体自动输出的开关（open_screen 列出的 controls 里的 fluidAutoOutput；关着就是 off）。按开（use_control）以后，它把罐里的流体往自己的输出面推；输出面挨着固化器，流体就进了固化器的罐。输出面朝哪边在机器存档数据的 mFacing 里（inspect_block 带 detail），界面上 sideSelection_… 那几个面板也是管这个的。这是改机器的设置，不会自己恢复。
  - 或者用流体单元：空单元拿到鼠标上去点提取机界面上的流体格装满，再到固化器的界面上点它的流体格倒进去（screens 手册）。
  - 两台之间通没通：看两边罐里的量变了没有（inspect_block、find_machines 都写着）。提取机的少了、固化器的多了，就是过去了。
- 然后：从覆盖板里取出模具（withdraw_items，容器带 side、sneak）→ process_items 固化器（模具在身上，它放进去、做完连同产物取回）→ 把模具放回覆盖板（deposit_items，同一个容器）。
- 上面每一步 process_items 不带 leave 都是在机器跟前等它转完；带 leave 是放下就走，回头来取。

# 凿子的花纹（Chisel）
- 很多建筑方块是“同一种东西的不同花纹”：结构混凝土有 16 种（chisel:nucrete/0 到 /15），圆石、荧石、各种石砖也是。图纸要的常常是其中某一个具体的 meta。
- 这些花纹之间不是配方：配方册里通常只有其中一种有做法，别的 find_recipes 查不到配方。它们属于凿子的同一个“组”，组里的任何一种都能用凿子变成另一种，一个换一个，不耗别的材料。
- find_recipes 查到这样的方块时，会把“凿子”当作又一种做法列出来：它在哪一组、同组还有哪些。全部变体：find_recipes 给 way "凿子"；程序里是那个结果的 data.chisel，或者 data.chiselGroupsOf(id, meta)（返回 [{ group, ore?, member, variants: [{ id, meta, name }] }]）。库函数 find_uses 反过来回答“这块东西能凿成什么”。
- 有的组还认一个矿辞名：带这个矿辞名的东西自己不在组里，也能凿成这一组。
- 凿子是拿在手里的工具（find_item "凿子" 找得到几种），不是机器。怎么用见 screens 手册的“凿子”。它用一次掉多少耐久，资料里没有。
- 算总料时带上凿子的一步：`await tool('total_materials', { id: 'chisel:nucrete', meta: 7, count: 4392, recipes: [做 /0 的那条配方的编号], chisel: [{ id: 'chisel:nucrete', meta: 7, from: { id: 'chisel:nucrete', meta: 0 } }] })`。它把这一步当成一个换一个往下乘；两样东西不在同一组时会说明各在哪一组。

# 卡住了、缺东西时
- 查到某一层不知道怎么继续（没有配方、要的机器没有、流体看不到、几条路你分不出好坏）：把已经查到的链、卡在哪一样、试过什么告诉主人，问他。不要硬编一条路，也不要只说“做不了”。
- 报“缺什么”时报到底：不是“缺玄钢板”，而是做玄钢板那条路上真正没有的那样东西、差多少、卡在哪台机器（没有、没电、电压或炉温不够）。中间那几层怎么来的也顺带说一句，主人手里要是有现成的中间件，给那个也行。
- 主人说“仓库里明明有”：find_in_storage 只看得到已加载区块里的容器，机器和总线里的东西是另算的。问主人东西放在哪，用 at 以那里为中心再查。
- 主人教你的做法、偏好（“板一律走卷板机”“模头去压模机里借”）：一两句的用 remember，成套的用 write_manual 写成你自己的手册，下次照办。
- 多步的目标把进度用 remember 记下来（目标、做到第几步、还缺什么），办完了 forget。
- 说到物品和机器，一律用工具结果里的中文名，原样说，不要自己翻译或换说法。

# 同一种东西两个 id
- GregTech 把登记在同一个材料件矿辞名下的东西当成一种：玄钢锭有 EnderIO 的和 GregTech 的两个 id，矿辞名都是 ingotDarkSteel。机器配方里写的是其中一个，后面标着 (or any ingotDarkSteel)，放哪个都行；高炉出来的也是其中一个。
- 所以库存要按矿辞名查（find_in_storage 的 ore），不要只查配方上写的那个 id。process_items 会自己用你身上有的那种。
- 手工合成里点名某个 id（没有写 any xxx）的格子只认那一个。

# 手工合成（craft_item）
- 给 recipe（配方的 # 编号）和 count（要几个成品）。原料怎么摆由配方定，你不用管。
- 汇总里写着 fits your 2x2 grid 的随身就能做；needs a crafting table 的要工作台或匠魂合成站：不用给 table，工具会找离你那时最近的一个走过去。只有主人点名要用哪个台子时才给 table。
- 原料和工具必须已经在身上。以 no_material 失败时 missing 列出每样还差几个。
- 以 invalid 失败时看消息：附近没有工作台就先走到一个旁边；合成格里有别人摆的东西就换一个；摆好后出来的不是要的东西，是这条配方在这个服务器上不成立，换一条或问人。

# 用机器做（process_items）
- 给 machine（机器的坐标，find_recipes 的 CAN RUN NOW / CAN TRY 后面和 find_machines 里都有；多方块机器给它的主机）、recipe（# 编号）和 rounds（做几轮）。要放什么、放多少、设几号编程电路、预期出什么，工具照配方算。
- 哪个 mod 的机器都行，原版熔炉也行：只要是带界面、能放东西的方块。身体读得懂状态的（GregTech 的）会先告诉你它行不行；读不懂的（find_recipes 写 CAN TRY）就是放进去试，配方没列的东西（熔炉的燃料）要自己加进 inputs。没见过的机器怎么对付，见 screens 手册。
- 消耗的原料要带够（配方的量乘轮数）。模具、模头这类“stays in the machine, not used up”的是物品，要带一个在身上，做完会连同产物取回来。
- 模具本来就放在那台机器里（主人留在原料格里的）：给 moldInside: true，就不用带、也不会再放一个进去。那是主人摆好的，用完留在原处。
- 不照配方、自己写 inputs 时：列出要放进去的每一样和数量；不消耗的（模具）写 1 个；配方没列而机器要的（熔炉的燃料）也写进去。
- **编程电路不用带**：配方里的 programmed circuit N 由工具直接设在机器上（多方块设在输入总线上），做完恢复原样。不要去找、去做编程电路这个物品。
- GregTech 的机器要满足：跑这类配方、等级不低于配方的、有电（蒸汽机器是有蒸汽，读不出来，只能试）、没在忙、没被关。find_machines 能看到每台的状态（默认看你身边 32 格；机器在别处时给 at，以那个地方为中心看）。
- 一批要等一会儿，量大时把 wait 调大。结果里有 timedOut 是没等到做完：做好的已经取回来了，剩下的还在机器里。
- 等的这段时间你在哪：不带 leave，这个任务从放料占着你到取完产物——机器转多久，你就在它跟前站多久。带 leave: true，料放进去、机器一开工任务就结束。
  - 这时产物和没消耗的模具留在机器里，之后用 withdraw_items 取：container 给这台机器是取产物，加 fromInputs: true 是取原料格里的（模具在那）；多方块取输出总线。
  - 任务结束时的结果写着这台机器一轮多久、这几轮大概还要多久。机器转完不会有消息来；find_machines、inspect_block 写着它还忙不忙。编程电路这时不恢复，结果里有现在是几、原来是几。
- 以 invalid 失败、说机器没开工时，原料已经拿回来了。看结果里的原因：NO POWER、SWITCHED OFF 告诉主人；有电又空闲的，对着配方查是缺模具、缺流体、电压或炉温不够，还是输出口满了，不要原样重试。

## 多方块机器（工业高炉这类）
- find_machines 里标着 multiblock 的是它的主机，下面列着它的输入输出总线和仓。STRUCTURE NOT COMPLETE 的用不了，告诉主人。
- 原料会放进输入总线，产物从输出总线取。高炉的配方有炉温要求（coil heat）：机器的炉温不够的那条，find_recipes 会标 NOT on the machine(s) here。
- 配方要流体（配方里写着 mB … (fluid)）：输入仓已经接着这种流体（find_machines 里看得到仓里有什么、有多少）就不用管；没有的话，带上装着这种流体的单元，用 fluids 给。产物是流体的留在输出仓里，你取不了。
- 输出总线写着 keeps nothing: pushes into … 的，产物会被推到旁边的箱子里：工具会按配方去那个箱子取。
- 有好几个输入总线时默认用最空的那个；要指定就给 bus（那个总线的坐标）。自己写 inputs（不给 recipe）而产物会被推到旁边箱子里时，用 expect 列出要从那个箱子取回的产物。
- 总线、仓上标着 AUTOMATED（接着漏斗、管道）的，是主人自动化的一环：输入总线可能一直是满的，放不进去时不要去清它，问主人。

# 还做不了的
- 单方块机器的流体格：罐里有什么，inspect_block 看得到。拿单元往里倒、往外装，是打开界面后用 use_control 点那个流体格（screens 手册；还没实测过）。
- 要点界面里的按钮、要改界面上的设置才开工的机器：open_screen 把界面上格子以外的控件也列出来，use_control 按或者设（screens 手册的“界面上格子以外的东西”）；格子用 click_slot 点。界面一个控件都列不出来、点了也没反应的，告诉主人。机器外面的按钮、拉杆是方块，空手 use_item 能按。
- find_recipes 里写着 you cannot run this yourself 的方式：那不是机器也不是合成（信息页、在世界里发生的事），得主人来，或者换一种方式。

# 别忘了
- 取料、合成、加工可以一次排好队（排在后面的传 queue: true），每个任务结束时你都会被叫醒；队列里还有任务在等时，不要再用不带 queue 的任务把它们顶掉。
- 步骤多而且一样（做一串中间件、一样样取料）时，可以写一个例程一口气做完，见 routines 手册。
- 为了办主人交代的事，取用他基地仓库里的材料属于正常干活；一次拿很多（要好几组，或者会把某样东西拿光）时说一声。标着 AUTOMATED 的箱子和总线，见上面“哪些是主人自动化的一部分”。
- 仓库、工作台、常用机器的坐标用 remember 记下来，下次直接用。
