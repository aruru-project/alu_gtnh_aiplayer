要吃东西、穿装备、右键用一件身上的东西、空手右键一个方块（按钮、拉杆、抽屉的某一格），或者往随身的背包这类包里放东西、取东西时看。

# 看与点实体（动物、怪物、玩家等）
- look_around 只是摘要。库函数 `list_entities {radius?,at?,page?}` 逐只列出稳定身份 uuid、维度 dim、注册种类 kind、名字 name、精确小数位置 pos、motion 和 state。state 有存活/燃烧/生命/幼年等观察；羊有毛色 woolColor、对应掉落方块 meta 的 woolMeta、是否已剪 sheared；动物有爱心状态 inLove。每页20只，data 是 `{entities,total,offset,more}`，more>0 继续翻页。动物会动，分页不是冻结快照；合并按 uuid 去重。
- 只看一只：`list_entities {entity:{uuid,dim}}`；`detail:true` 给非玩家实体自己的存档状态，`path` 精查其中一部分（语法和 inspect_block 一样，省略处会写明；玩家私人存档不提供）。查询不到时如实失败，不会换成另一只。
- 动作：`use_item {id:"minecraft:shears",entity:{uuid,dim}}` 是拿剪刀右键选中的那只；拿小麦喂动物换成 `id:"minecraft:wheat"`。`entity` 和 `on/side/hit` 不能同时用；不传 id 是空手。`left:true` 攻击该实体，伤害/保护/PvP由游戏判断。`times` 对两种按钮都是点击次数，攻击 times:2 就是打两下，默认只一下；不是自动战斗。
- 身体会正常走近，跟着目标的新位置重新找路；每次点之前复查同维度、存活、3格实体触及距离和视线，不隔墙或隔着别的实体点。消失/换维度、走不到、追60秒没追上、被保护拒绝，都照实失败，已经点了几下也保留。
- 结果里 clicks/entityEvents 是尝试次数/到达正常游戏事件的次数，不等于做成了目的。比较 entityBefore/entityNow 的 state、gained/lost、newNearbyDrops（点前后新出现的掉落物）。例如红羊剪成了应看到 sheared false→true、毛色仍红、新掉落 minecraft:wool meta14；已剪的羊再点没变化就没再剪出东西。掉落留在地上，需要时另用 collect_items，身体不直接发物品或任务奖励。

# 用一件东西（use_item）
- use_item 是玩家点击的通用办法：把身上的一件东西拿到手里，对着空中右键，或者对着某个方块（on）、实体（entity）右键；不给 id 就是空手点目标。left:true 是左键，点实体就是攻击。吃东西、喝东西、穿戴装备、打开一件物品自己的界面、试一件没见过的物品、按按钮、扳拉杆、开门，都是它。
- 存取东西、合成、放方块、用机器各有专门的工具，它们替你走路、数数、把结果说全；use_item 是玩家那只手本身，专门的工具够不着的事用它。
- 点方块的哪里由你定。side 是点哪个面（down / up / north / south / west / east）：给了水平的面，身体先走到那个面的正前方；不给就点朝着你的那个面。hit 是点在方块里的哪一点（x、y、z 各 0–1，从方块最低的那个角算起）：不给是那个面的正中间。只认正面、按点的位置分格子的方块（抽屉的每一格、一块面板上的几个按钮）靠这两个。
- 空手左键会先选空快捷栏格；快捷栏满但背包有空格时，用正常换格把手中一组移进背包。两边都没有空格才会以 inventory_full 停下。clicks:0 表示一次也没点，不是把左键改成了右键。
- times 是连着右键几下（1–64），every 是两下之间隔几 tick（默认 4）：就是玩家连点、按住右键。中途打开了界面就不再点；手里的东西用光了，后面几下是空手点的。结果里 clicks 是实际点了几下。
- 例（抽屉的“双击全放”）：手里拿着一种东西对抽屉那一格的正面点一下，放进去的是手里那一组；连点两下，第二下是双击，身上所有这种东西都进去。`use_item { id: "minecraft:dirt", on: { x, y, z }, side: "south", hit: { x: 0.25, y: 0.75, z: 1 }, times: 2 }`，身上 3 组 192 个泥土一次全进去，不到一秒。每一格的正面朝哪、该点哪一点：库函数 list_drawers 的 data.slots 里每格的 front 和 hit，原样填进 side 和 hit。
- 例（空手）：`use_item { on: { x: 7, y: 65, z: 5 } }` 空手右键那个方块一下：按钮被按下，拉杆被扳过去。对一个带界面的方块（箱子、机器）空手右键会打开它的界面，身体马上把它关掉，结果里写着 it opened a screen；要留着界面自己点，用 open_screen。
- 它做了什么由那件物品自己决定，你只看得到痕迹。结果里：gained / lost 是背包里多了、少了什么（吃掉的食物、穿到身上去的装备在 lost 里），health 是血量，food 是饱食度，还有是不是打开了界面。
- 装水、装岩浆：use_item 拿着空桶或空单元，on 给液体的源方块（find_blocks 结果里不带 /数字 的那些；带 /数字 的是流动的液体，桶和单元装不了）。身体会走到看得见那一格的地方，看着它右键，像玩家那样。结果写着看的是哪个面、装上了什么；这一格被装走以后旁边的水可能流回来，也可能不流回来（一格大的水坑装一次就没了）。在液面下面的、四面都被挡住的看不见，任务以 out_of_reach 失败并写明。倒水：拿着水桶对着要倒的那个方块的面用（比如坑底的上面），水进的是那个面外面的一格。
- 本包 IC2 空单元的世界装水走“点方块”回调，不走空气右键。实测：深水里 crosshairNone 时空单元不变，同位置空桶能装水；看穿水源且准星能点到浅水底/岸边实心方块时，空单元能装成水单元。流体注册表列出水单元只表示有这种装满的物品，不等于任何右键姿态都能装。
- 你点的是看得见的那个面：身体先走到看得见它的地方。找不到时照旧隔着东西点，结果里会写明（faceUnseen）。点方块没起作用时，身体会像玩家的游戏那样再对着视线用一次手里的东西（结果里写着 also used in the air），桶装水倒水、吃东西都是这一下。
- 拿着方块对着一个面右键，方块进的是那个面外面的一格（点的是草、薄雪这类一碰就让开的东西时，是它自己那一格），不是点的那一格：结果里写着那一格点之前、现在是什么（the cell on that face, (x,y,z), where a block from the hand goes, was …, now …）。没进去时写着原因（那一格被什么占着、有什么站在里面、方块自己的规矩不让它立在那里，比如梯子要贴着实心方块；点的是箱子、机器这类有界面的方块又没蹲着，点击给了它，打开的是它的界面：对着它放要 sneak: true）。成批放和方向确实存在方块 meta 里的种类，用 place_blocks（blockMeta），见 terrain 手册。抽屉等把方向存在方块自己的数据里，不能把方向数字塞给 blockMeta；inspect_block 的 Front 会报告实际正面和来源。
- 对着方块用的，结果里还写着那一格点之前是什么、现在是什么（the block there was …, now …），方块变了、被带走了都看得出；带数据的方块（机器、箱子），还写着它自己存的数据里哪些值变了（its saved data changed: mFacing 1 → 4），朝向、设置、覆盖板被点改了都看得出。GregTech 的机器用工具点哪一点改哪一面，见 gregtech 手册。
- 结果写着 nothing visible changed 是没看出任何变化：这东西多半不是这样用的。换一种用法试一次（给 on 对着方块用，sneak: true 蹲着用，或者 left: true 左键），还不行就告诉主人；同样的用法再试结果也一样。
- left: true 是左键点那个方块一下（按下就松开）：对按下有反应的东西照样反应，要挖一会儿的方块不会被挖掉。例（凿子原地凿花纹）：凿子左键凿成什么，看它界面的输入格里放着什么。先把要的那种样子（一个就够，比如结构混凝土/3）放进凿子界面的输入格再关上（open_screen 给 item 打开凿子，click_slot 把它放进去），然后 `use_item { id: "chisel:chisel", on: { x, y, z }, left: true }`，那一格就在原地变成那种样子，结果里写着方块从什么变成了什么。输入格空着时，左键是把方块换成同组的下一种（/7 → /8 → /9）。每凿一下凿子掉一点耐久。实测过（测试服，结构混凝土）。
- sneak: true 是蹲着右键。有些东西蹲着用是另一个意思（比如穿到身上而不是打开）。
- 探险背包 mod 的直升机背包、喷气背包、探险背包右键是打开它的界面；穿到背上是按界面里的 equip 按钮，见 wear 手册。
- 给了 on，默认 approach:"walk" 会先接近方块；累计接近最多60游戏秒。已经悬停且够得着时可以直接点，需要接近却持续空中3秒时失败，不改装备。
- `approach:"current"` 只用于 on 方块：从当前真实眼位按 side/hit 检查触及和视线，不够就失败，不会先走。这适合保留精确站位放置、悬停点选。抽屉朝向存在 tile.Dir，不是 blockMeta；站在想让正面朝向的一侧，持抽屉点支撑面的合适位置，再 inspect_block 核对 Front。视线向上/下超过65度时，原生抽屉会朝下/上。
- 用了会发生什么由那件东西自己决定，有的会改掉或带走方块（手推车会把容器整个带走，见 containers 手册）。主人教过怎么用的，照他说的用；不认识、拿不准的东西，对着主人的机器和箱子用之前问一句。

# 游戏机制与动作后的变化
- GTNH 的锄地规则不完全等同原版：任务6“一分耕耘……”说明水源附近才能开垦农田，远水的草地用锄会翻成泥土并可能掉种子。先查本包条件，不因没出现耕地就判断工具坏了。
- 倒出的水会继续流，可能冲掉火把、花草或改变附近易受水影响的地面。临时硬化混凝土等操作可先做有底、有围挡的水槽，确认出水侧与附近易损物，再倒水；收回水源后仍需查看周边，不能把“桶收回来了”当成场地已恢复。
- use_item 的目标格前后状态和背包变化，不是整个邻域所有后续变化的清单。植物生长、草蔓延、水流和机器运行会随时间继续发生；比较两次查询要看时点和这些条件，不把不同时间的状态自动当成回执矛盾。

# 吃
- 饱食度是“当前状态”里的 food，满是 20。默认设置下你不掉饱食度，不用吃。
- 主人打开了饥饿、饱食度低了：用 use_item 吃身上的食物。身上没有就去仓库取，或者跟主人要。

# 随身的包（背包这类）
- 右键能打开一个界面的物品（小背包这类）可以当容器：deposit_items / withdraw_items 不给 container，改给 bag（包这件物品的 id，要分颜色、型号时带 meta）。不用走路，在原地打开。
- 包要在你身上。刚做出来的包已经在身上；在箱子里的先取出来。
- 往包里放必须用 items 列出放什么、各多少（不列的话不知道该留什么）。包本身不会被放进它自己里面。
- 主人说“把东西放进包里”而没说是哪些东西：按上下文是刚才那批就放那批，拿不准就问。
- 看包里的内容：`open_screen {item:{id,meta?}}`，格子清单会把包里和自己的背包分开列；用完 close_screen。往外取时数量不够，会在结果的 missing 里说。
- no_material 是你身上没有这个包。invalid 表示用“空气右键”没有打开可存取界面，也可能是打开方式不对，不代表它没有物品界面。
- 有些物品要潜行点方块才开界面。`open_screen {item:{id},at:{x,y,z},sneak:true}` 保留这次点击的上下文，界面保持打开，接着 click_slot 操作；还可带 side/hit。bag 只走空气使用，不包含这套方块点击上下文。寻矿魔杖的样本格是这一类。
- 用 use_item 去“用”一个包，结果只会说它打开了一个界面（已经关上）；要看和自己点，用 open_screen 按相同物品、方块和潜行方式打开。
