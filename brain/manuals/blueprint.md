主人让你照图纸（.schematic 文件）盖建筑时，动手之前看。

# 准备
- 你能照 Schematica 的图纸把建筑的框体盖出来。图纸存在服务器上，用 list_blueprints 看有哪些；没有主人要的那张，就请他在控制面板的“图纸”页上传。
- 图纸不旋转、不镜像。x y z 是图纸最小角落（x、y、z 都最小的那个角）放在世界的哪里，和 Schematica 里显示的原点一致。放在哪由主人说了算：他没给坐标就问，不要自己猜。

# 先对比，再动手
- 动手前先用 check_blueprint（参数和之后的 build_blueprint 一样）。它只看不动，告诉你：已经对上多少、要放哪些材料（各要多少、你身上有多少）、哪些得由人来放、有什么挡着、按你给的 clear 会挖掉什么。
- 然后简短地告诉主人这四件事：要清掉什么、有什么挡着不会动、缺什么材料、哪些得他自己放。没有需要他先点头的事（见下面 clear 那一条），说完就可以开工。
- 检查结果开头写着 INCOMPLETE（有格子所在的区块没加载）时，数字不完整：先走到工地跟前再查一次。

# clear：哪些挡路的方块可以挖
- 不给 clear 就一块都不挖，被挡住的位置直接跳过。
- "natural"（泥土、草方块、沙子、沙砾、雪、树叶这类天然地形）和 "plants"（花、灌木、树叶、作物这些长出来的东西）你可以自己决定给。
- 除此之外的任何方块（原木、石头、旧建材……），或者检查结果显示会挖掉不是天然地形的方块，都要先问过主人、他同意了再给：那可能是别人盖的东西。
- 带数据的方块（箱子、机器）、液体、基岩无论如何都不会被挖。

# 它放什么、不放什么
- build_blueprint 只放“放下去就是图纸要的样子”的普通建筑方块。带内容或朝向的方块（箱子、抽屉、楼梯、原木、火把、机器、管道）你放不了，结果里算在 byHand（得由人放）。如实告诉主人这些要他自己来放，不要说成已经全盖完了。
- 材料先从背包拿，不够时去 supply 给的容器取（箱子、抽屉都行）。开工前对着 check_blueprint 的材料清单看身上和 supply 里够不够，不够就先跟主人说缺什么、缺多少。材料不齐也能开工：能放的会先放完，最后任务以 no_material 结束并列出每种还缺多少。
- 要清掉的东西多时给 dropoff；建筑材料会留在身上，不会被卸掉。

# 大图纸
- 一次任务最多覆盖 64×64 列。更大的图纸用 x1,x2 和 z1,z2 切成不超过 64×64 的块，楼层用 y1,y2 一层层分，然后排队做（queue: true）。这几个范围用的是世界坐标，要成对给。
- 任务先从上往下挖掉允许挖的挡路方块，再由低到高放。楼板和屋顶是站在上面铺的，所以你不会把自己封在里面；做完时你站在建筑顶上。
- 用同样的参数再执行会接着做：已经对的格子不动。

# 看懂结果
- 任务结束时（成功或失败），结果里的 now 是此刻世界和图纸的对比：done 已经对上、toPlace 还空着你能放、byHand 得由人放、blocked 被别的方块占着、extra 图纸上是空的位置却有方块。后面列着还要放的材料、得由人放的、还挡着的各是什么。
- toPlace 不是 0 就是还没盖完。任务“完成”也要看一眼 byHand 和 blocked，把剩下的告诉主人。
- 以 no_material 失败时，能放的已经先放了，missing 列出每种材料还缺多少：取够了或者请主人补上，再用同样的参数重跑。
- 结果里有 needsClimbingBlocks 时，是高处够不着、身上又没有垫脚的方块：跟主人要一些泥土或圆石，拿到后用同样的参数再跑一次。
