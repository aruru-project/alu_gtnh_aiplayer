# 首轮开发与验证记录（2026-11-10）

范围：从零做出身体（mod）和大脑（brain），全部在测试实例上验证。没有碰正式服、正式存档和任何真实的模型 key。

## 环境

- 测试实例 `testserver/`：从正式实例只读复制的 GTNH 2.9.0 整合包（298 个 mod），全新世界，游戏端口 10186，RCON 25576，bridge 25591，内存 6G。
- 编译：GTNH 官方 mod 模板，JDK 25 跑 Gradle，产物是 Java 8 字节码。
- 大脑：Node 24 直接执行 TypeScript，无运行时依赖。

## 验证了什么

| 怎么验证的 | 结果 |
|---|---|
| `tools/scenario.py`：通过 bridge 指挥一个 bot，然后直接查世界里的方块和箱子 | 22 项全过。走到指定位置；6×6 坡地整平后每一列都在目标高度；砌出的四面墙每一块都在、里面是空的；清掉后全空；存 70 取 7 数量分毫不差、缺货如实报告；两箱之间搬运不动 bot 自己的东西；`/sethome` `/home` 及其报错；没镐挖石头报 `no_tool` 且方块还在 |
| 同一脚本的安全项 | 伪装成指令的聊天（4 种写法）都只是聊天；允许列表外的指令被拒；5000 格外的目的地被拒；溢出的坐标被拒；没有签名的皮肤被拒 |
| `brain: npm test`、`npm run typecheck` | 184 项通过，类型检查无报错 |
| `brain: npm run live:testserver`：真实的大脑进程连真实 mod，模型换成本机的模拟服务（OpenAI 兼容和 Anthropic 兼容两种线格式各跑一半） | 15 场全过：面板下指令 → 看地形 → 平地 → 任务结束被叫醒 → 回话；清空带自动卸货再填回；存、取、搬、捡、递东西给另一个玩家；`no_material` `invalid` `unreachable` `no_tool` 四种失败后的再唤醒；大脑重启后靠补发的事件接上 |
| 手动：12×12、最高 15 层的山坡整平，中途重启测试服 | bot 自己重新上线，任务接着做完。共挖 864 块、填 45 块，约 12 分钟，服务器保持 20 TPS |
| 手动：两个 bot，一个带路一个 `follow` | 上坡下坡都跟得上 |
| 手动：关掉无敌后让它掉出世界 | 收到受伤和死亡事件，任务以 `interrupted` 结束，约 1.5 秒后自动重生，之后照常干活 |
| 手动：`/kick` | 下线并保持下线，再 `bot.spawn` 回到原位 |
| 手动：ServerUtilities 领地（一个 bot 建队并认领区块） | 队外的 bot 挖、放、开箱子都以 `denied` 失败，方块和箱子没动；被邀请并 `team join` 后都能做 |
| 手动：`skin Alu set Notch` | 服务器上的 PierceSkinRestorer 接受并保存 |
| 浏览器打开面板 | 概览、模型表单正常显示（`docs/img/`） |

独立代码评审（只读，对照反编译的 1.7.10 源码）提出的问题里，会出事的都已修掉并复测：聊天可被当成指令执行、跨维度上线会走原版传送门逻辑、箱子界面没打开时绕过保护直接读写、无签名皮肤会把看到它的真人踢下线、坐标溢出可卡死主线程、指令过密会被服务器当刷屏踢掉，等等。

## 还没证明的

- **真人客户端看到的样子**：它的走路动作、转头、挖掘动画、皮肤显示，都只从服务器这一侧确认了数据是对的，没有用客户端看过。
- **真实模型**：两种接口的请求格式只对着模拟服务验证过；模型拿到这些工具后实际聊得怎么样、会不会乱来，没有试过。
- **正式服**：没有部署。
- **长时间无人值守**：最长一次连续运行是十几分钟的整平任务。
- **主世界以外的维度**、**GT 机器的界面**、**门**：没做，也没测。

## 已知的限制

- 不会开门。关着门的房间走不进去；可以在房间里给它设一个 home，让它传送进去。
- 高处够不着时会用泥土、圆石垫脚，干完会拆；拆不到的会在任务结果里报个数。
- 走路先找不动地形的路，确实走不通才挖（只挖泥土、沙子、树叶这类）。所以它出不了石头围成的深坑，除非身上有垫脚的方块。
- 只在自己站的那个维度干活；任务中途被带去别的维度会停下。
- 步行上限 256 格，更远要先 `/home`。
- 服务器重启时正在做的 `withdraw` 会重取一份，`haul` 手上那趟货会留在它身上。
- 打开“会饿”后它不会自己吃东西。
