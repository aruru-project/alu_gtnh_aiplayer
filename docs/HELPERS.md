# 帮手：对话和干活分开

状态：**设计稿，还没实现**（2026-11-11）。实现时以这份为准，改了设计先改这里。

## 为什么要有

现在大脑里只有一个代理：一个模型、一份上下文、一条线。它在一步步想和试的时候（一轮 3–9 次模型调用，30 秒到 2 分钟），别人说的话只能排队；"步间收消息"（见 `BRAIN_SPEC.md`）把等待缩到一步以内，但还有三件事解决不了：

- 回话的速度受"一步多长"限制：模型越大、上下文越长，一步越久（实测 18 万 token 的输入，每步 11–13 秒）。
- 聊天混进干活的上下文：每回一句话都带着整段工作记录，又慢又贵；干活的思路也被闲聊打断。
- "停"取决于干活的那位想到哪一步了。

不占模型的活已经是分开的：身体的任务（盖、搬、走）和例程（它写的后台脚本）都在后台跑。要分开的只是**需要动脑的长活**：查一棵很深的配方树、连着做二十样中间件且每样都要判断、对着一张大图纸备料。

## 概念

- **主代理**：就是这个 AI 玩家本人，跟人说话的那个。有名字、人设、记忆。
- **帮手**：主代理自己开的子代理。有自己的模型、自己的上下文、自己的活动日志；领一件事去做，做完或卡住时向主代理汇报。帮手不是另一个玩家：对游戏里的人来说只有一个 Alu。
- 开不开帮手、把什么交给帮手，**由主代理自己决定**。这是给它的一项通用能力，不是固定的流程：简单的事它照旧自己做。

## 主代理多出来的工具

| 工具 | 作用 |
|---|---|
| `start_helper {task, hands?, model?, withContext?}` | 开一个帮手去做 `task`。马上返回帮手的 id；帮手在后台干。`hands:true` 表示这件事要动手（见"手只有一双"）。`model` 从主人配置的模型里挑，不给就用"帮手默认模型"。`withContext:true` 把主代理最近的对话摘要带给它 |
| `message_helper {id, text}` | 给帮手带话（补充要求、回答它的问题、让它改方向）。帮手在下一步看到 |
| `helper_status {id?}` | 帮手现在在干什么：最近几步、用了多少步和 token、有没有在等回答。不给 id 就列出全部 |
| `stop_helper {id}` | 停掉帮手。它开的任务和例程一并取消，手交还 |

帮手的汇报和最终结果作为事件到达主代理（用"步间收消息"的同一个机制：主代理正忙时下一步看到，空闲时被叫醒）。

## 帮手有什么

- 和主代理同一套工具和库函数、同一份本地资料、同一批手册，只有这几处不同：
  - **不能对玩家说话**（没有 `say` / `whisper`）。要告诉主人的事，用 `report` 告诉主代理，由主代理说。这样游戏里只有一个声音，主代理也始终知道"自己"说过什么。
  - 多两个工具：`report {text, question?}`（中途汇报或提问；`question:true` 表示它在等回答）；做完时最后一段文字就是结果，自动送给主代理。
  - 不能再开帮手（只有一层）。
  - 能读主代理的记忆和手册；写记忆、写手册照常（那是"同一个人"学到的东西）。
- 系统提示词：核心部分和主代理相同，加一段事实说明——你是 X 的帮手，X 在跟玩家说话；你领了什么事；怎么汇报；卡住了问 X（X 不知道会去问主人）。
- 自己的对话历史和压缩；自己的步数上限。

## 手只有一双

身体只有一个，任务队列也只有一条。两个代理同时往里排任务会互相打架，所以：

- **同一时间只有一个代理"拿着手"**（能开身体任务、开会动手的例程、用界面动作）。默认是主代理。
- `start_helper` 带 `hands:true` 时，手交给这个帮手，直到它结束或被停。这期间主代理的动手类工具会如实返回"手在帮手 h2 那里：给它带话，或者停掉它"。主代理仍然可以：说话、看（所有只查不动的工具和程序）、管帮手、读写记忆和手册。
- 不带 `hands` 的帮手只能查（查配方、算材料、读图纸、看世界），可以同时开好几个。
- 已经有帮手拿着手时，再开一个要手的帮手会被拒绝并说明原因。
- 身体任务结束、例程结果这些事件，送给开它的那个代理。玩家说的话、面板指令、提醒只送给主代理。

> 以后可以让帮手带**自己的身体**（另一个 bot，mod 本来就支持多个）：那样几个身体能同时干活，也就不用抢手。这一版不做，但代理的数据结构里留着 `body` 字段（现在所有代理都是同一个名字）。

## 让主代理保持轻

分开之后主代理的上下文里只有对话、它自己做的短活、帮手的汇报，所以：

- 主代理的历史压缩阈值默认值调低（现在 24 万 token；实测 18 万时每步 11–13 秒），具体数值实现时按实测定，主人可调。帮手的阈值照旧。
- 帮手的每一步不进主代理的上下文；主代理想看细节用 `helper_status`。

## 上限（都是主人可调的设置）

- 同时最多几个帮手（默认 3）。
- 帮手每轮步数上限、总步数或总时长上限（到了就停下并把现状汇报给主代理）。
- 每日 token 上限是所有代理合计的。

## 重启

- 每个帮手的任务说明、对话历史、状态都落盘。
- 第一版：大脑重启后，帮手标成"被打断"，主代理收到一条事件（哪个帮手、做到哪了、它的最后一次汇报），由主代理决定重开还是不管。身体的任务照旧自己续做。
- 之后再做"帮手原地接着干"。

## 面板

- 代理列表：主代理 + 各个帮手，各自的模型、状态（空闲 / 正在想第几步 / 等回答 / 已结束）、有没有拿着手、已用步数和 token。
- 每个帮手可以点开看它自己的活动日志（和主代理的日志同一种视图），可以停。
- 日志条目和状态接口里的 `agent` 字段就是为这个留的。

## 不在这一版里

- 帮手带自己的身体。
- 主人一说话就打断主代理正在想的那一步（有了帮手之后主代理很少有长轮次，先看需不需要）。
- 帮手原地续跑。

## 实现时要验证的

- 主代理开了要手的帮手之后，主人说话 → 主代理在一步之内回话，帮手的活不受影响。
- 主人说"停" → 主代理停帮手 → 帮手的任务和例程都取消，手回到主代理。
- 帮手提问 → 主代理不知道 → 问主人 → 主人回答 → 主代理带话 → 帮手继续。
- 两个只查的帮手同时跑，互不干扰；它们的身体查询不抢队列。
- 帮手的任务结束事件只叫醒帮手，不叫醒主代理。
- 重启后帮手被标成"被打断"，主代理知道。
- 真实模型上：主代理会不会在该交出去的时候交出去、不该交的时候不交（这条只能靠实测，不靠规则）。
