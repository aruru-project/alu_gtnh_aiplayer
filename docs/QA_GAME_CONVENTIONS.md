# 游戏单位、背包准备与通用自查（f46/f48/f57/f62/f66）

本批来自正式服 794836d 的连续运行意见。目标不只是修动作，也包括补足容易让模型套用现实常识、或把普通游戏困难当故障的信息。没有改正式服配置、意见状态或游戏规则。

## f57：mB 不是 mL，GT 的 L 不应额外乘1000

意见中的“自行更正”不成立：小型木流体管标称200 L/s，对应200 mB/s，不是200,000 mB/s。mB是millibucket（千分之一桶），不是millilitre；1桶=1000 mB=1000 GT L。

核对安装的 `gregtech-5.09.54.265.jar`，不是从现实体积单位推导：

- `LoaderMetaPipeEntities.registerFluidPipes`：5101/5102/5103的小型、普通、大型木管的 `mCapacity` 分别为10/30/60。
- `MTEFluidPipe.getDescription` 把 `mCapacity × 20` 交给 `gt.blockmachines.fluidpipe.capacity.desc`，语言条目显示 `Fluid Capacity: %s L/sec`。正式导出提示对应200/600/1200 L/s。
- `getInfo/getCapacity` 和 `distributeFluid` 直接使用 Forge `FluidStack.amount`，没有升到mB的1000倍换算。`onPostTick` 每5 tick检查，并另看收液方向/状态；不能用一个分配周期倒推出整条管路的实际稳定通量，提示的标称每秒基准仍是20 tick。
- `/s`、`/sec` 与 `/t` 必须统一时间基准。标称管道流量不是整条产线的实测通量；本文不核定意见里所估锅炉需水750 mB/s本身是否正确，也不据此替模型选管。

改动：
- `find_item` 遇到含流体L数量的GT物品提示，原提示逐字保留，另附单位说明；程序结果增加 `unitNotes`。不是把本地资料数值改写成猜测的“正确值”。
- `inspect_block detail` 的GT扫描器原话含同类单位时，也在原话外说明。
- gregtech/crafting手册解释桶、mB、GT L和时间基准。其他mod含义不清的单位仍需单独核实，不把GT约定推给所有mod。

实际数据核对：从原 `find_item` 工具实现，用本机真实packdata分别查5101、5102、5103及苹果。改后原始tooltip/data.items与改前相同，三根GT管另有单位说明，苹果结果完全不变。没有为文案增加逐字锁定测试；相关工具/手册/上下文检查与typecheck覆盖接线。

## f66：区分流体管、线缆与机器

正式配置 `gt6Pipe=true`、`gt6Cable=true`。安装的 `MTEFluidPipe.onWrenchRightClick` 在普通工具模式下按九宫格求面：不潜行调用连接开关，潜行调用输入禁用开关。`MTECable` 则有剪线钳与电烙铁的连接操作。任务47a与正式顶管的扳手连接变化也相符。

因此修正gregtech手册：流体管用扳手，连接与输入禁用分清；剪线钳/电烙铁的线缆操作不再笼统称为“管道和线缆”。这不是增加专用动作或改GT规则。

## 背包与普通困难：用户明确要求的通用常识

- 干活线核心提示加入简短的开工准备与自查：连续工作先存放暂时不用的东西，为新堆栈、产物、返还和拆分留空间；失败按原因处理前置条件，不原样反复试，不立即报Bug。
- 详细操作放在containers/failures手册：Tools与Inventory只是同一36格背包的显示分组；一个空格未必够多产物/返还操作，零空格也不一定不能接收可堆叠物。容量与不可达分开，不机械地清背包代替查路径。
- 多投、少取却报成功、回执与真实库存矛盾，仍是要报告的引擎异常；“应该整理”不能成为数量错误的借口。动作层的容量分类和精确搬运由本批其他修复处理。

## f46/f48、f62：正常机制，不修改游戏迎合误解

任务6明确近水才能开垦、远水锄草可成泥土并出种子。两次查询之间的草/泥土差异可能受自然变化影响，现有日志没有证明回执读错；也没有证明具体那44秒一定发生了回草。

倒水后冲落火把、影响附近易损地面是游戏的连带变化，不是桶动作故障。inventory手册补充封闭水槽、查看邻域、收水后再核场地，以及目标格前后快照并不代表所有后续世界变化。没有添加水流预测器，也没阻止正常倒水。
