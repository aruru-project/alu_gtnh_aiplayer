# 对话和干活：一个玩家，两条线

状态：**设计稿，还没实现**（2026-11-11，主人定的方向）。实现时以这份为准，改了设计先改这里。

## 定位

AI 玩家就是一个玩家：一个名字、一个身体。但"跟人说话"和"操作身体干活"是两条线，各有自己的模型调用和上下文，互不等待：

- **对话的那条线**（下面叫"对话线"）：听人说话、回话、查资料。它**不操作身体**；要动手的事，交给干活线。
- **干活的那条线**（"干活线"）：操作身体的只有它。领到事就去做，做完、卡住、有发现时告诉对话线。它不直接对玩家说话。

对游戏里的人来说只有一个 Alu。

## 为什么这样分

现在只有一条线：它在一步步想和试的时候（一轮 3–9 次模型调用，30 秒到 2 分钟），别人说的话只能排队。"步间收消息"把等待缩到一步以内，但还有三件事解决不了：

- 回话的速度受"一步多长"限制：模型越大、上下文越长，一步越久（实测 18 万 token 的输入，每步 11–13 秒）。
- 聊天混进干活的上下文：每回一句话都带着整段工作记录，又慢又贵；干活的思路也被闲聊打断。
- "停"取决于干活的那位想到哪一步了。

分成两条固定的线，而不是"一个主代理按需开若干帮手、手在谁那里要交接"，是因为：身体只有一个，干活的本来就只能有一个；结构上分死了，对话线手里根本没有动手的工具，就不存在"它自己动手干了一件长活又聋了"和"手现在在谁那里"的问题。

## 对话线

- **收到**：玩家的聊天和悄悄话（带说话人的站位和指向）、面板指令、提醒到点、干活线的汇报和提问、要紧的身体事件的简报（死了、被踢下线）。
- **能做**：
  - 说话：`say`、`whisper`。
  - 查：所有只查不动的工具和库函数——物品、配方、任务书、图纸和多方块结构数据、看世界、看背包和容器、`run_program`。这些不占身体的任务队列，干活线忙着也能查。
  - 记：记忆、提醒、手册、意见簿。
  - 派活和管活（见下）。
- **不能做**：任何会让身体动的事（走、挖放、存取、合成加工、用物品、界面动作、会动手的例程、服务器指令里会动身体的那些）。它的工具清单里没有这些。
- 每一轮给它的状态里带一行"干活线现在在干什么"（空闲 / 在做什么、第几步 / 在等你回答什么），所以它不用问就答得出"你在干嘛"。

对话线多出来的工具：

| 工具 | 作用 |
|---|---|
| `tell_worker {text}` | 把一件事交给干活线，或者给它带话（补充要求、回答它的问题、让它改方向）。马上返回；干活线空闲时立刻开始，在忙时下一步看到。**主人的原话和指向信息会自动原样附上**，不靠对话线转述 |
| `worker_status {detail?}` | 干活线现在在干什么：最近几步、身体正在做的任务、例程、有没有在等回答 |
| `stop_work {}` | 让一切停下：取消身体的任务队列和例程、打断干活线正在想的那一步。**不需要干活线配合**，一次调用生效；干活线随后会知道自己被叫停了 |

对话线可以在同一步里一边回话一边派活（先说"好，我去拿"，同时 `tell_worker`），所以主人不会等。

## 干活线

- 就是现在的那个代理去掉"对玩家说话"：全部动手的工具、界面动作、例程、同一份本地资料和手册、同样的"卡住就问"。
- **收到**：对话线交来的事和带的话（附主人原话）、身体任务结束、例程结果、身体事件（受伤、死亡、重生）。
- 多一个工具 `report {text, question?}`：中途汇报、有发现、或者提问（`question:true` 表示它在等回答）。一轮结束时留下的文字自动作为结果送给对话线。
- 它**有自己连续的上下文**（知道自己刚才把什么放在了哪、哪台机器里还有东西），自己压缩历史。不是每件事开一个新的。
- 能读最近的聊天记录（只读），省得每句话都靠转述。
- 记忆和手册两条线共用，都能写：那是"同一个人"学到的东西。

## 两条线各用各的模型

主人给两条线各选一个模型（可以一样）。例如对话线用回话快的，干活线用想得深的。面板上两张状态卡，各显示自己的模型、状态（空闲 / 正在想第几步 / 接口故障）和日志；例程和身体的任务归在干活线下面。

对话线的上下文里只有对话、它查的东西、干活线的汇报，所以它的历史压缩阈值默认调低（具体数值按实测定，主人可调），回话才快。

## 代价和我们怎么对付

- **多一道手**：每件要动手的事多一次模型调用（对话线派 → 干活线接）。对话线先回话再派活，主人感觉到的是"它马上应了，手稍后动"。
- **传话走样**：主人的原话和指向信息由程序原样附给干活线；干活线能读聊天记录。
- **两个上下文说不到一块**：对话线每轮的状态里有干活线的现状；想知道细节用 `worker_status`；干活线的汇报进对话线的上下文。
- **对话线变成传声筒**：它自己能查资料、看世界，问"直升机背包怎么做""箱子里有多少铁"这类事它自己答，不用惊动干活线。
- **花费**：两份上下文。对话线轻；总量比现在高一些。

## 重启和没人在的时候

- 两条线的历史和状态各自落盘，重启后各自接上；身体的任务照旧自己续做。
- 主人不在线时干活线照常把手上的活做完，汇报给对话线；对话线没人可说就不说，记下来，主人回来问时答得出。

## 上限（主人可调）

- 两条线各自的每轮步数上限。
- 每日 token 上限是两条线合计的。

## 不在这一版里

- 第三条线（比如专门做长时间调研的只读帮手）。先看两条线够不够。
- 主人一说话就打断对话线正在想的那一步（对话线的轮次本来就短，先看需不需要）。

## 实现时要验证的

- 干活线正连着做一串事时，主人说话 → 对话线一步之内回话，干活线的活不受影响。
- 主人说"停" → `stop_work` 一次生效：任务、例程都取消，干活线正在想的那一步被打断，它之后不会自己接着干。
- 主人指着一个方块说"把这个拆了" → 干活线拿到的是原话和指向的坐标，不是对话线的转述。
- 干活线提问 → 对话线自己答得了就答，答不了问主人 → 主人回答 → 带话 → 干活线继续。
- 主人问"你在干嘛" → 对话线不调工具也答得出大概；问细节时用 `worker_status`。
- 对话线的工具清单里确实没有任何会动身体的工具；它直接调这类名字时如实告诉它"这要交给干活线"。
- 身体任务结束的事件只到干活线；玩家说的话只到对话线。
- 重启后两条线各自接上。
- 真实模型上：对话线会不会把该自己查的事也推给干活线、该派的事派得清不清楚（只能靠实测，不靠规则）。
