# 架构

目标：GTNH 服务器里有一个 AI 玩家，按生存规则干活（平地、挖、填、盖、搬运），主人在不在线都能继续。

```
┌──────────── Minecraft 服务器进程 ────────────┐        ┌────────────── 大脑进程（brain/）──────────────┐
│  mod/  “身体”                                │        │                                               │
│                                              │  TCP   │  bridge 客户端 ── 工具（tools）               │
│  AI 玩家实体（真的 EntityPlayerMP）          │ 一行一 │        │                  │                    │
│  动作层：寻路、挖、放、开箱子                │  JSON  │        ▼                  ▼                    │
│  任务层：goto / flatten / fill / haul …      │◄──────►│   agent 循环  ──────►  模型调用层（llm/）      │
│  感知：状态、地形扫描、箱子、聊天            │        │   事件 → 一轮决策       OpenAI 兼容 / Anthropic 兼容 │
│  bridge 服务端（只监听本机）                 │        │        │                                       │
└──────────────────────────────────────────────┘        │   记忆、历史、配置（本地文件）   网页面板       │
                                                        └───────────────────────────────────────────────┘
```

## 分工原则

- **身体不懂语言，大脑不碰世界。** 身体只执行确定性的动作和任务；大脑只通过 `docs/PROTOCOL.md` 里的方法观察和下令。
- **花时间的事都是任务。** 大脑启动任务后就结束这一轮决策；任务结束时身体发事件，大脑再醒来。bot 干活期间不消耗模型调用。
- **身体自己能把活干完。** 任务队列存在世界存档里，大脑挂了、模型接口断了、服务器重启，已经下达的任务照样继续。
- **按玩家规则动手。** 挖掘走原版的挖掘流程（时间、工具耐久、掉落都照算），放置要有可依附的面，操作有触及距离，物品来自背包和箱子。
- **改大脑不重启游戏。** 提示词、模型、决策逻辑都在大脑进程里。

## 大脑内部的分层

| 层 | 职责 | 不许做的事 |
|---|---|---|
| `llm/` 模型调用层 | 把统一的“消息 + 工具”请求翻译成某一家的接口并解析回来；重试、超时、用量统计 | 不知道 Minecraft，不知道 agent |
| `agent/` 循环 | 收事件、组上下文、调模型、执行工具调用、直到这一轮结束；步数和预算上限；历史压缩 | 不直接发 HTTP，不直接读写 socket |
| `tools/` 工具 | 模型能用的每个动作的定义（名字、参数 schema、执行函数），内部调 bridge | 不含策略 |
| `bridge/` | 协议客户端：连接、重连、请求、事件流 | – |
| `panel/` | 网页面板和它的 HTTP API | – |
| `store/` | 配置（含密钥）、记忆、历史的落盘 | – |

新增一家模型接口 = 在 `llm/` 加一个适配器文件并注册；agent 循环不用改。

## 仓库布局

```
mod/         Forge 1.7.10 服务端 mod（GTNH 官方模板）
brain/       大脑服务（TypeScript / Node）
docs/        架构、协议、运行记录
tools/       开发脚本（构建、测试服、bridge 调试）
testserver/  完整 GTNH 测试实例，不入库
```
